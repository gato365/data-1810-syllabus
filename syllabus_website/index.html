Term structure at a glance

Fifteen weeks in four color-coded blocks: Foundations weeks 1–2 · Data (ETV) weeks 3–9 · CS weeks 10–12 · STAT weeks 13–15, followed by a cumulative common final on Saturday, December 12. Midterms are on Wednesday of weeks 5 and 9; the third is Wednesday of week 13 because Veterans Day falls on Wednesday of week 12.

Course description

Catalog description

In practice, this course teaches you to work with real data in R from start to finish. It moves through four blocks, each with its own instructional rhythm:

Foundations · weeks 1–2

Course systems, the R environment (Positron), project-based file management, storage magnitudes, variable assignment, data and container types, and the pipe. Rhythm: See it → Define it → Apply it.

Data (ETV) · weeks 3–9

Fourteen class meetings = fourteen complete Extract → Transform → Visualize cycles on real datasets. Import/export, cleaning, and visualization are learned inside the cycles; ethics is infused throughout. Rhythm: context & ethics → question → E → T → V → answer.

CS · weeks 10–12

Programming constructs motivated by the data work: control flow, loops and accumulators, purrr map(), and writing and debugging functions (packaging an ETV workflow into a function). Rhythm: Motivation → Definition → Practice.

STAT · weeks 13–15

Statistical questions and hypothesis testing on datasets the class already knows: one-way ANOVA, chi-square, and simple linear regression — one reproducible .qmd report built from scratch each week. Rhythm: the seven-step statistical investigation workflow.

Role of the course within the program

The course serves the Statistics B.S. Program Learning Objectives (PLOs) below — mainly PLO-5 software mastery and data management, with contributions to PLO-1, PLO-3, and PLO-4.

By the end of this course, a successful student will be able to:

  1. Foundations Explain the R interactive development environment, variable assignment, the different R data and object types, and R packages.
  2. Data Import and export data in tabular formats.
  3. Data Perform data cleaning and introductory data management with numeric, character, factor, and date variable types.
  4. Data Produce and interpret appropriate data visualizations and numerical summaries for categorical and numeric data.
  5. CS Explain the components of introductory iterative code including for and while loops.
  6. CS Compare vectorized or R repeated functionality to manual loops.
  7. CS Explain how logical operations and conditional execution of code are employed to solve data management/analysis tasks and control function input/output.
  8. CS Describe R function definition nomenclature, inputs and outputs, and scoping.
  9. Data Develop and execute R reproducible documents that contain code or results to solve data management/analysis tasks. used throughout; formally assessed in the follow-on course
  10. STAT Produce and explain output for introductory statistical inferences.
  11. Data Identify and adapt R functionality independently through help documentation and other resources (e.g., textbooks, websites).
  12. STAT Recognize and describe the biases and potential ethical implications that arise from mishandling missing values, low response rates, or groups with small sample sizes.

R + Positron

All coursework is done in R using the Positron IDE with project-based file management (R/ for scripts, Data/ for raw and processed data).

Quarto

Labs and STAT-block reports are written as Quarto (.qmd) documents; labs progress from fill-in-the-blank scaffolds to documents built from scratch.

Drill app

Spaced-review drills are completed in the course drill app (~4×/week, 5–20 minutes each). You will receive a token/name and the rules in week 1.

Description
  • Purpose: demonstrate, without outside help, the skills practiced in the notes, drills, and labs.
  • All exams are cumulative. Once an outcome first appears on a midterm it stays eligible on every exam after, including the final. Each exam emphasizes its most recent weeks (see Section 6).
  • Format: midterms are 20 questions, given on Wednesday of weeks 5, 9, and 13, and take 60 minutes; 10–15 minutes of that class period is still devoted to a Check-In. The common final is 35 questions on Saturday, December 12; the time is TBD.
  • Question types: exam and check-in questions come in 14 consistent forms. Types 1–4 read supplied code and critique it; types 5–14 produce — write, complete, predict, calculate, interpret, or reflect.

Guidelines for succeeding in the course
  • Do the drills as scheduled (~4× per week, 5–20 minutes each) — spaced review is how the material sticks, and drills preview the hard topics before they are taught.
  • Come to every class: each meeting in weeks 3–9 is a complete Extract → Transform → Visualize cycle, and Check-Ins happen in class.
  • Treat labs as rehearsal for exams — exam questions reflect the skills practiced in the notes, drills, and labs, and every exam is cumulative.
  • Keep a clean project: R/ for scripts, Data/ for data, and cache what you extract (write_csv() habit).
  • Learn to read help documentation and other resources (CLO 11) — independence is a graded skill.
